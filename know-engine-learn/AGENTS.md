# 开发约束

- Java 代码必须保持项目既有格式化风格；提交前运行格式化工具，但不要改写用户已完成的格式化结果。
- 注释遵循阿里巴巴 Java 开发手册：类、类属性和类方法使用 `/** ... */` 格式的 Javadoc，不得以 `//` 代替对外 API 的文档注释。
- 所有抽象方法（含接口方法）必须使用多行 Javadoc，说明用途、实现功能、调用注意事项或实现约束，并按需包含 `@param`、`@return`、`@throws`。
- Controller 和 Service 的公开方法必须使用多行 Javadoc；实体、DTO 的每个字段必须有简洁、准确的中文业务注释。
- 所有枚举字段必须注释其对应数据项的业务用途。
- Javadoc 必须位于其声明和全部注解之前，禁止将注释置于注解与类、字段或方法声明之间。
- 方法内部单行注释放在被注释语句上方并使用 `//`；多行说明使用 `/* ... */`，且与代码保持对齐。内部注释优先解释业务原因、边界条件或约束，不重复代码已清晰表达的行为。
- 修改代码时必须同步更新受影响的参数、返回值、异常与核心逻辑注释；中文表述优先保证准确清晰，专有名词和关键字保留英文原文。
- `TODO`、`FIXME` 等特殊标记必须写明标记人和标记时间；`TODO` 应尽量补充预计处理时间。
- 方法、构造器与局部变量使用表达业务含义的完整名称；禁止使用 `r`、`d`、`s` 等单字母变量名，循环索引除外。
