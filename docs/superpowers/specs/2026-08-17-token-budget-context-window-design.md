# Token 预算与上下文窗口控制设计

## 目标

在每次 `ManualReactAgent` 调用模型前，为输入上下文应用固定 2,000 Token 的近似预算，降低上下文窗口溢出与无控制成本增长的风险。

本阶段使用字符近似估算：每四个字符计为一个 Token，并为每条消息增加固定协议开销。该数字不是模型账单或模型响应中的实际 usage，而是发送前的本地保护阈值。

## 范围

预算应用于每次 `model.decide(...)` 的输入快照，包括系统提示、用户消息、助手文本和工具调用、工具响应及其参数。运行上下文仍保留完整消息链，数据库中的会话记忆与成功运行轨迹不被删除、覆盖或截断。

本阶段不接入模型专用 tokenizer、不记录响应 usage、不新增前端面板、不改变最近五轮持久化会话记忆窗口，也不修改工具超时、取消、并发或 SSE 事件类型。

## 架构

新增纯 Java 的 `CharacterTokenBudget`，由 `ReactRunContext` 在创建模型消息快照时调用：

```text
ManualReactAgent
  → ReactRunContext.messagesWithinBudget(CharacterTokenBudget)
    → 预算内不可变 Message 快照
      → ReactModelPort.decide
```

`ManualReactAgent` 继续持有完整运行状态并在 `boundedElastic` 工作线程调用模型。预算器没有 Spring、数据库、Reactor 或模型 SDK 依赖，因此可用确定性单元测试验证。

## 裁剪规则

预算器按原始消息顺序识别以下不可拆分组：

- 系统提示组：始终保留。
- 当前用户问题组：始终保留。
- 历史问答组：一条历史用户消息与紧随的助手回答一起保留或丢弃。
- 工具交互组：携带 ToolCall 的 AssistantMessage 与其紧随的 ToolResponseMessage 一起保留或丢弃。
- 其他助手文本组：作为单条最近运行消息保留或丢弃。

先计算系统提示和当前用户问题的估算消耗；再从最新组向最旧组累加，直到加下一组会超过 2,000。超限时整组丢弃最旧内容，绝不拆开 ToolCall 与 Observation，也不修改组内文本。

若系统提示与当前用户问题本身超过预算，预算器抛出明确异常。Agent 将它转换为稳定 `error → complete`，不调用模型、不发送最终 text，也不写会话记忆或成功运行轨迹。用户问题不会为了满足预算而被悄悄截断。

## 数据与生命周期边界

裁剪仅影响一次模型调用所见的快照。完整 `ReactRunContext` 仍用于工具调用关联、取消检查、成功轨迹工具名和最终回答持久化。下一轮模型调用重新从完整上下文生成预算快照，因此同一轮不会因临时裁剪损坏内部状态。

取消先取得终止权时，预算器不产生新的 SSE 或持久化行为；超时 Observation 仍按工具交互组规则参与预算。预算器不保存或展示模型内部思维链。

## 测试策略

- `CharacterTokenBudgetTest`：验证字符近似计算、协议开销、预算边界、历史裁剪、最新优先与工具交互原子性。
- `ReactRunContextTest`：验证当前问题和系统提示被保护、完整上下文未被快照裁剪修改，以及超大必保留内容拒绝。
- `ManualReactAgentTest`：验证超预算时模型不被调用、只输出稳定错误和完成事件，且不写成功记忆或运行轨迹。
- 回归：工具超时、取消、并发、会话记忆、运行轨迹、SSE 和完整模块测试保持原语义。

所有功能遵循 TDD：先加入并实际运行失败测试，再编写最小实现。
