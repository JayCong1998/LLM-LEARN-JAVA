# 新电脑会话交接提示词设计

## 目标

在 `dodo-agent-learn/NEXT_SESSION_PROMPT.md` 中提供一份可以整体复制到新 Codex 会话的中文提示词，使新会话仅依赖 Git 仓库即可恢复本项目的学习目标、架构背景、开发规范、当前进度和后续任务。

## 内容结构

交接提示词按以下顺序组织：

1. 明确新会话的角色：先理解参考项目与学习项目，再继续教学式迭代开发。
2. 指定必须完整阅读的 `AGENTS.md`、阶段教程、第三阶段设计稿和实施计划。
3. 要求检查 Git 分支、工作区、提交历史和现有代码，禁止覆盖未提交修改。
4. 总结第一、第二阶段成果，以及第三阶段 Task 1～5 的已完成状态。
5. 指定下一步从 Task 6 前端记忆面板开始，随后执行 Task 7 教程与整体验收。
6. 固化直接在 `master` 开发、逐行中文注释、TDD、SSE 与阻塞线程边界等规则。
7. 列出关键提交，帮助新会话通过 `git show` 精确恢复实现演进。
8. 提供恢复检查命令、测试命令和完成判定，要求基于实际输出汇报。
9. 明确不得读取、输出或提交真实 API Key，配置只使用环境变量。

## 路径与可移植性

- 文件放在学习项目根目录，便于克隆后立即发现。
- 提示词只使用以仓库根目录为基准的相对路径，不包含 Windows 盘符和用户名。
- 开发资料统一位于 `docs/superpowers/`，学习教程统一位于 `dodo-agent-learn/tutorials/stages/`。

## 使用方式

用户在新电脑克隆仓库后，打开 `dodo-agent-learn/NEXT_SESSION_PROMPT.md`，复制其中“交接提示词”代码块的完整内容，作为新会话第一条消息发送。新会话必须先完成只读检查和上下文总结，再继续修改代码。

## 不包含的内容

- 不记录真实 API Key、机器绝对路径或本地环境变量值。
- 不复制大段已有设计和教程正文，而是要求新会话读取权威源文件。
- 不声称第三阶段已经结束，也不提前编写尚未完成的第三阶段教程结论。

## 验收标准

- 文件在新电脑上无需修改路径即可使用。
- 新会话能够明确说出项目目标、阶段进度、下一任务及代码规范。
- 新会话不会重复 Task 1～5，也不会覆盖用户工作区修改。
- 新会话会从 Task 6 开始按 TDD 开发，并在 Task 7 生成第三阶段教程。
